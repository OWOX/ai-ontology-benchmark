Setup holds the API keys and the project status. Save a key for each provider, or use Upload .env file: it reads a local text file of NAME=VALUE lines (ANTHROPIC_API_KEY, OPENAI_API_KEY, GOOGLE_API_KEY), saves each key it knows into secrets/, and ignores everything else. It is a shortcut for pasting the keys one by one. Install dependencies and Run tests prepare and check the project.1Setup

Shapes picks the release and the puzzles to test. Every input of a chosen puzzle in that release goes to every AI model under all three setups. The input count on each card is the number of inputs in the release. Choose at least one puzzle.2Shapes

Models lists the AI models from the catalogue, grouped by provider. Tick the ones to test. A model is disabled, with the reason shown, when its provider has no API key or its token price is missing from config.3Models

Parameters sets the experiment. Attempts is how many times each input is sent to each AI model under each setup, and the retry cap limits retries of infrastructure failures. The three budgets stop a run that would cost too much. Estimate and Dry run show the cost and the plan, and Run starts the experiment.4Parameters

Stopping may leave a request in flight that is paid for and never recorded. For small runs, prefer a limit.

Progress shows every attempt as it lands, with its outcome: success, failure, hallucination, malformed output, or infrastructure failure. A hallucination means at least one impossible move. The Cube panel replays an attempt's moves state by state on the input's puzzle. Live follows the newest attempt of the model you choose.5Progress

Evaluate re-validates every raw response of the experiment under a release and writes the experiment report. It never calls an AI model. Commit opens a preview of the branch and files, and on confirmation commits the results and opens a pull request. Commit needs a report that is newer than the raw records.6Evaluate and commit
