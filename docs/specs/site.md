# site

`src/site/export.py`, `src/site/metrics.py`, `config/site.toml`, `site/`, and `.github/workflows/pages.yml`. Exports the data for the public results page and builds and publishes it from `site/`. The files under `site/src/components/islands/` and `site/src/lib/benchmark.ts` are ported from the personal site, and `site/src/lib/types.ts` holds the types they use. Terms are defined in [definitions.md](../definitions.md).

## Inputs

1. `config/site.toml` at `--ref` (default `origin/main`): `title`, `description`, `intro`, and `min_release`, a release version (a missing or malformed field is a checked error). Only experiments whose `experiment.toml` release is at least `min_release` are shown.
2. `docs/definitions.md` at `--ref`.
3. Every experiment with at least one `raw/*.jsonl` file, found as a `results/<id>/` folder at `--ref` or as a `<remote>/results/<id>` branch (`--remote`, default `origin`). When both exist for one id, the branch wins, as in the UI architecture rule 1 of AGENTS.md. Its `experiment.toml`, raw files, and `results/<id>/prices.toml` are read from the folder at `--ref` or from the branch ref. The `releases/<experiment release>/inputs.jsonl` and `manifest.json`, and the fallback `config/prices.toml` (the same order `evaluate` uses, checked by `src.config.check_prices_table`), are always read at `--ref`. A folder or branch without a raw file is skipped with one stderr line naming it.

The script first runs `git fetch --prune <remote>` (`--remote`, default `origin`) with the refspecs `+refs/heads/main:refs/remotes/<remote>/main` and `+refs/heads/results/*:refs/remotes/<remote>/results/*` in one call and a 60 second timeout, so `<remote>/main` and the result branches are current, unless `--no-fetch` is given. It reads git objects only, never the work tree.

## Scoring

Every raw record is scored again by the assessment in this checkout, whatever release made it: `make_attempt_rows` from `src/evaluate/metrics.py` is called on the records, the inputs of the experiment's release, the prices, the config's decision models (providers in `DECISION_PROVIDERS`), and whether the release's manifest has `mismatch_reasons` (false when absent). `load_release` is not called, because it refuses a release whose assessment differs from the current one, which is expected here. A record whose input is not in the release's `inputs.jsonl` is not scored and is counted as skipped.

## Output

`--out` (default `site/.data/site.json`), one JSON file:

```json
{ "page": { "title": "", "description": "", "intro": "" },
  "legalMoves": { "2x2": [] },
  "prompts": { "3.0.0/no_model/v1": "the exact prompt text" },
  "definitions": [ { "key": "precision", "name": "Balanced precision", "definition": "" } ],
  "metrics": [ { "puzzle": "2x2", "model": "", "provider": "",
    "attempts": 10, "tokens": 12345,
    "precision": { "value": 0.5, "n": 10 }, "hallucination": { "value": null, "n": 0 },
    "critical": { "value": null, "n": 0 } } ],
  "setupMetrics": [ { "puzzle": "2x2", "model": "", "setup": "no_model",
    "precision": { "value": 0.5, "n": 10 }, "hallucination": { "value": null, "n": 0 },
    "critical": { "value": null, "n": 0 } } ],
  "experiments": [ { "experimentId": "", "release": "", "branch": "main", "puzzles": [], "models": [{ "name": "", "provider": "", "kind": "", "decision": false }],
    "setups": [], "attemptsPerInput": 3, "attemptCount": 0, "firstAt": "", "lastAt": "",
    "attempts": [ { "model": "", "puzzle": "", "inputId": "", "validity": "valid", "setup": "", "attempt": 1,
      "depth": 5, "state": "", "corruption": null, "moves": [], "outcome": "", "mismatch": false } ] } ] }
```

`legalMoves` holds, for every puzzle in the exported attempts, the list from that puzzle's engine `legal_moves()` (`src.puzzles.registry.get_engine`). The page passes it to the player, which uses it to find the first impossible move of an attempt. No move list exists in `site/`, so invariant 14 holds.

`prompts` holds the exact prompt each attempt's AI model received, once per release, setup, and input id (the key is `<release>/<setup>/<input id>`, so repeated attempts and experiments on one release share one entry). The text is `build_prompt` from `src/run/prompts.py`, filled from the input record of the experiment's release and the template `releases/<release>/prompts/<setup>/<puzzle>.txt`, both read through git at `--ref` and never from the work tree (the templates go into a temporary directory first). Before a release's prompts are built, the export recomputes the release's prompt versions with `prompt_versions` from `src/run/prompts.py`, from the templates and inputs read at `--ref`, and compares them with the manifest's `prompt_versions`. When they differ, or a template is missing or invalid, the release gets no prompts, with one stderr line naming it, so the page never shows a prompt the AI model didn't receive. A decision model's first call receives this prompt followed by its move history, so the entry is the part of its request that is the same for every input. `prompts` is not part of the data the index page inlines: `site/src/pages/attempts.json.ts` serves it with the attempts.

`decision` of a model is true when its provider is in `DECISION_PROVIDERS` (`src/run/models.py`). The player uses it to add a note under a decision model's prompt.

`branch` is `main` for an experiment read from the folder at `--ref`, and `results/<id>` for one read from its branch. The page uses it to link an attempt's raw results.

An attempt's `outcome`, `mismatch`, and `moves` come from the scoring above (`outcome`, `mismatch`, `parsed_moves`), so the player agrees with the charts.

`metrics` is built by `src/site/metrics.py`: one row per puzzle and AI model, sorted by puzzle then model, pooled over every setup, depth, and experiment, followed by one row per AI model, sorted by model, with `"puzzle": "all"`, pooled the same way and over every puzzle too. The three metrics follow the same rules on the pooled rows. `setupMetrics` is built by `setup_metric_rows` in the same file: one row per puzzle, AI model, and [setup](../definitions.md#setups) (`no_model`, `descriptive`, `prescriptive`, in the order of `SETUPS` in `src/run/prompts.py`, any other setup after them by name), sorted by puzzle, model, then setup, followed by the rows with `"puzzle": "all"` pooled over every puzzle, sorted by model then setup. A row holds `puzzle`, `model`, `setup`, and the three metrics below, computed from the group's rows exactly as for `metrics` (a group that has no value gets null with its `n`, as for a decision model's hallucination rate). It has no `provider`, `attempts`, or `tokens`, and `metrics` keeps its shape. The same `min_release` filtering applies, because both lists are built from the same rows.

`provider` is the first provider other than `unknown` in the experiments' `[[models]]`. With `everything` the group's scored rows and `rows` those whose outcome is not `infrastructure_failure`, every `value` is null when it is n/a, and `n` is its denominator:

1. `attempts` and `tokens`: the number of `everything` (every scored row of the group, infrastructure failures included, so unlike the three metrics it leaves none out), and the sum over `everything` of `input_tokens`, `output_tokens`, `retry_input_tokens`, and `retry_output_tokens` as stored in the raw records. The page sums them over the rows its filter shows, for the Source note.
2. `precision`: [balanced precision](../definitions.md#metrics) over the classified answers of `rows`. `n` is the number of classified answers.
3. `hallucination`: the [hallucination rate](../definitions.md#metrics), over the rows that gave moves. Null, with `n` 0, when none did and when every row is a decision-model row.
4. `critical`: [critical thinking](../definitions.md#metrics), over the rows from releases with mismatch reasons only. Null when either validity label has none of them. `n` is the number of those rows.

It prints one line: experiments, attempts, skipped.

## Rules

1. Experiments are sorted by id. Attempts are sorted by model, puzzle, input id, setup, attempt number, and creation time.
2. An experiment whose release is below `min_release` is skipped with one stderr line naming it and its release. It adds nothing to `experiments` or `metrics`.
3. Attempts with outcome `infrastructure_failure` are dropped from `experiments` and are left out of every metric.
4. A model absent from `[[models]]` gets provider and kind `unknown`.
5. An experiment folder or branch with no raw file is skipped with one stderr line and does not fail the export. One whose records are all infrastructure failures gets no entry in `experiments`, with one stderr line, but its rows still count in `metrics`. A missing `experiment.toml`, `release`, input file, release `manifest.json`, or price for a model is a checked error: exit 1, naming the ref and the file or experiment.
6. The skipped count in the printed line adds records whose input is not in the release and raw lines that do not parse as a record.
7. `definitions` holds the items of the `## Metrics` section matched by bold name: `precision` is "Balanced precision", `hallucination` is "Hallucination rate", and `critical` is "Critical thinking". Markdown is stripped to plain text. A name not found is left out, with one warning line on stderr per name.
8. `attempts.json` is `{ "attempts": { "<puzzle>": [...] }, "prompts": {...} }`. Each attempt there has `prompt`, the key of its entry in `prompts`, when the export built one. `prompts` holds only the entries those attempts point at.

## The page

The Puzzle filter has no "All" option. Its options are the puzzles with data, drawn as cube thumbnails and exposed as toggle buttons with `aria-pressed` (radios cannot be switched off). No puzzle selected means all puzzles, and it is the default. Clicking an unselected puzzle selects it and replaces any other; clicking the selected one again unselects it. With none selected, the chart reads the `metrics` rows with puzzle `all`, the Model and AI provider filters list every model and provider, and the Experiment Example picks an attempt of any puzzle and draws that attempt's own puzzle. The hash writes `puzzle=` only for a selected puzzle, so the plain page has none; `puzzle=all` and any unknown value read as none selected. The options are at full opacity while none is pressed and faded next to a selected one, and the group has an `aria-describedby` hint, "None selected shows all puzzles." Without `all` rows in the data, the first puzzle with data is selected by default and cannot be unselected.

The Puzzle and AI provider filters sit side by side in two equal halves (`minmax(0, 1fr)` each), with the Model filter below at full width. The puzzle options wrap onto more lines when they do not fit their half, never overflowing or scrolling sideways. At 36rem (576px) and narrower, including a 390px phone, the halves stack, so each filter has the full width and the page has no horizontal scroll.

`site/src/components/islands/benchmark/BenchmarkView.tsx` shows three metric tabs, in this order, with `precision` the default (a `#metric=` value that is not one of the three falls back to it, so the old id `cost` shows Precision, except that the old id `detection` means `critical`):

1. Precision (`precision`), a percentage, higher is better.
2. Hallucination rate (`hallucination`), a percentage, lower is better.
3. Critical thinking (`critical`), a percentage, higher is better.

Each metric chart sits in a section with a subtitle (an `h2`) and one plain sentence under it. There are two sections, in this order: "Metrics by AI model" (Charts 1 to 3) and "Metrics by setup" (Charts 4 to 6). Both are `MetricChart.tsx`, with the tabs, the "?" definitions, and the popover described here; only the bars differ. The setup section is left out when `setupMetrics` is absent or empty, and its tab is its own state, not in the hash.

In the panel, each chart is a `<figure>`: the bars, then a `<figcaption>` under them, so the caption comes after the chart in the DOM. The figure is named by the caption (`aria-labelledby`), and the bars keep their own `role="img"` name, which lists every label and value. The caption reads "Chart N. <metric> by <AI model or setup>", in italics, where N follows the section's tab: 1 to 3 on the AI model tabs and 4 to 6 on the setup tabs, and the metric is "Balanced precision", "Hallucination rate", or "Critical thinking". After it come two upright buttons. The first is "(?)", text-styled like "Prompt" in the player (a dashed underline), with accessible name "About Chart N", `aria-expanded`, and `aria-controls` pointing at a `role="dialog"` that is always in the DOM and hidden while closed, with `aria-label` "About Chart N". The dialog opens upwards over the bars, or below the caption when there is no room between the caption and the bottom of the sticky header, and is placed again on scroll and resize while it is open. The "(?)" and the copy button sit in one no-wrap group, so they stay together on the caption's last line. It closes on Escape (focus returns to the "(?)" only when it was inside the caption), on a click outside its chart's caption, and when the tab changes. At most one popover is open on the page: opening the metric's definition ("?" on the tab) closes the title's in the same chart and the other way round, and the player's popovers close on a click outside the player, in a chart or anywhere else. The tab "?" buttons of the setup chart are named "What is <metric>? (by setup)". The dialog text is one to three plain sentences on what the chart shows and which question it answers (docs/methodology.md, "The question"). The AI model charts answer which AI models get the answer right, hallucinate, or spot an impossible puzzle. The setup charts address the research question: does giving an AI model the rules of a puzzle change how often its answers are right, how often it hallucinates, and how well it judges whether a puzzle can be solved. Their text also says each bar is the average over the selected AI models that have a value under every setup, each counting equally.

The second button is the copy button, a monochrome icon (two sheets) with `aria-label` "Copy Chart N to clipboard" and `title` "Copy chart", shown on every chart that has bars. A click (`copyChart.ts`) writes one `ClipboardItem` with `image/png` and `text/plain`. The PNG is drawn on a `<canvas>` from the chart's data, not from the DOM, with no library: 640 CSS px wide at 2x, in the light theme's colours on white whatever theme the page is in, the bars with their labels and values and the best and worst colours of the page, then the caption in italics, then in small text the filter ("All puzzles" or "<puzzle> cube", and the number of AI models), the setup chart's note, and the page URL (origin and path, without the hash). Every text is cut with an ellipsis (`measureText`) to fit: a bar label stops 12px short of its value, and the caption, filter, note, and URL stop at the image's inner width. The text is the caption, then one "label: value" line per bar (`n/a` for no value), then the filter line and the setup chart's note, the same lines as under the image (not the URL). Without `ClipboardItem` or `clipboard.write`, or when that write fails, only `navigator.clipboard.writeText` gets the text. On success the icon is a check for 1.5 s and a `role="status"` `aria-live="polite"` region reads "Copied"; when nothing can be written the region reads "Copy failed", shown beside the button.

The setup chart has one bar for each of "No model", "Descriptive model", and "Prescriptive model", in that order. For the selected puzzle (`all` when none) and the ticked AI models, a bar is the unweighted mean of the `setupMetrics` values of those AI models for that setup (`setupBars` in `site/src/lib/benchmark.ts`), over complete cases: an AI model counts only when it has a row and a value under every setup shown, so all three bars average the same AI models and can be ranked against each other. An AI model with a null value under any setup (the hallucination rate of a decision model) is left out of all three bars. Each AI model that counts weighs the same whatever its attempt count; within an experiment every setup sees the same inputs. A bar with no value reads `n/a` and has no bar. Once under the bars, a muted line says "Averaged over N AI models.", with " M left out for lacking a value under some setup." added when some are left out. With no AI model selected the chart shows "No model selected.", as the AI model chart does. Colour, scale, and ranking are the AI model chart's, and the same filter drives both charts.

A bar runs on a fixed 0 to 100% scale. A null value reads `n/a` and has no bar. Best and worst are ranked on the text shown. On a narrow screen the tablist scrolls sideways, its scrollbar hidden and its tabs unwrapped, and a "?" button follows its tab, hiding when the tab is scrolled out of the tablist, which also closes its open definition. Selecting a tab scrolls the tablist, never the page, until the tab is fully shown.

The Experiment Example (`Player.tsx`) shows State, Model, and Result. After the result comes an external-link icon (`ExternalLinkIcon`, a box with an arrow out of its top-right corner) linking to the raw results of the case in a new tab, with accessible name "Source (opens in a new tab)" and title "Source", and a hit area of at least 24px. The Result line is laid out before Run, hidden, so Run never moves. Its title row ends with a refresh icon button ("Show another case", always enabled, also while a run plays, when a click stops the replay and shows another case in its unplayed state; absent when there is no other case), whose icon is 1em of the title's font size. In the Model line, "Prompt" is a button styled the same way. It opens a popover with the exact prompt the AI model received for that attempt, in a monospace, pre-wrapped box that scrolls past a maximum height and fits a 390px phone. When the attempt's model is a decision model (`decision` in the exported data), one short note under the prompt says it also received the moves so far and the list of options with each call. An attempt without a prompt has no button. The prompts come from `attempts.json`, not from the page data. The State line of an unsolvable input reads "State: 4x4 cube, not solvable", with no corruption text; "not solvable" is a button. The two buttons look exactly like inline text: no background, padding, or border, the inherited font, a pointer cursor, and a dashed underline, with a visible `:focus-visible` outline. The "not solvable" popover opens with the corruption description in bold, capitalized and ending in a full stop (for example "Twisted corner DBL anticlockwise."), followed by one or two plain sentences on why legal moves can't reach the state, chosen by the corruption type (the first two words of the corruption description): `twisted corner`, `flipped edge`, `flipped wing`, `swapped corners`, `swapped edges`, or `recoloured sticker`. The flipped edge text says every legal move flips an even number of edges, so one flipped edge can't be reached. Any other type gets a generic sentence. A popover has a border and a shadow from the theme tokens and a z-index above the player. It is always in the DOM, hidden while closed, has `role="dialog"` and an `aria-label`, and its button has `aria-expanded` and `aria-controls` pointing at it. A popover toggles on a click of its button and closes on Escape (focus returns to the button) or a click outside. The outside click is not stopped, so a click on Run or the reload icon both closes the popover and does that control's action. Only one popover is open at a time.

Under the intro paragraph and above the "About the project" line, static HTML in `index.astro` (not the React island, so it is in the served page) holds a quiet notice with `role="note"`: a small monochrome warning icon (an inline `aria-hidden` SVG triangle with an exclamation mark, stroked in `currentColor`, about 1.1em, aligned with the first line) and the text "Preview only. The benchmarks shown here are preliminary: research is in progress, and experiment data is still being collected." It uses muted text and a thin rule from the theme tokens, in both themes, and wraps at 390px.

Below the Experiment Example is a Source section (`Source.tsx`), in the look of the other sections, with the GitHub mark as its icon (an inline SVG in `icons.tsx`, drawn with the theme tokens). It holds a link reading "github.com/OWOX/ai-ontology-benchmark" to the repository, and a note. The note starts with the attempts and tokens behind the data shown, for example "12,345 attempts and 67.8 million tokens.": the sums of the `attempts` and `tokens` of the `metrics` rows for the selected puzzle (the `all` rows when none is selected) and the models shown, so it follows the filter, and it is left out while no model is shown. Attempts use en-GB thousands separators; tokens are in millions with one decimal from a million up, in thousands with `k` below that ("12k"; rounded before the unit is chosen, so 999,999 reads "1.0 million"), and plain under a thousand. The note goes on: the repository holds the experiment design (methodology and definitions), the frozen releases with their inputs and prompts, every AI model's raw answers, and the code that scores them, and every number on the page is recomputed from those raw answers. The footer holds only the theme switcher.

## SEO and share card

`site/src/components/SEO.astro`, ported from the personal site and used by `Layout.astro`, writes the head fields. Title and description come from `page.title` and `page.description` of `config/site.toml`, with no suffix added:

1. `robots` is `index, follow`, the canonical and `og:url` are `https://owox.github.io/ai-ontology-benchmark/`, and the icon is `public/favicon.svg`, a 1x1x1 cube.
2. Open Graph: `og:title`, `og:description`, `og:image` (absolute URL of `og.png`), `og:image:width` 1200, `og:image:height` 630, `og:type` `website`, and `og:site_name`. Twitter: `twitter:card` `summary_large_image`, `twitter:title`, `twitter:description`, and `twitter:image`.
3. JSON-LD, with `<` escaped as `\u003c`, passed by `index.astro`: a schema.org `Dataset` with name, description, url, `license` (CC BY 4.0, the licence of the data; the code is Apache 2.0, see the README), `isAccessibleForFree`, `creator` (Organization OWOX), and `sameAs` (the repo).

`site/scripts/og-card.tsx`, ported from the personal site's `scripts/og-cards.tsx`, renders `site/public/og.png` (1200x630) with Playwright from `site/.data/site.json`: the title, the description, the `OneCube` drawing (`site/scripts/OneCube.tsx`, a 1x1x1 cube in the style of CubeView, used only by the card), and a horizontal bar chart of balanced precision per AI model for the `all` rows, best first, at most 6, with the model names as the page shows them. It uses the page's colour tokens and fonts, and fails when the fonts don't load. `npm run og:card` runs it, and `OG_CHROME` names a Chrome binary to use in place of Playwright's Chromium. The card is generated and gitignored, so it always matches the exported numbers.

## Build and publish

After the export, `npm ci`, `npx playwright install --with-deps chromium`, `npm run og:card`, and `npm run build` in `site/` build the static page and its share card. Publishing is the manual `workflow_dispatch` workflow `.github/workflows/pages.yml`, which runs the export with `--ref origin/main`, builds, and deploys `site/dist` to GitHub Pages. The export fetches `main` itself. The workflow reads data and `config/site.toml` from `origin/main`, so dispatch it from `main`. It has no other trigger.

## Test

`tests/test_site.py` also covers the `setupMetrics` rows: grouping by puzzle, model, and setup in setup order, the pooled `all` rows, n/a values, and that the `metrics` rows keep their shape. It builds a throwaway git repo with a main commit that holds the releases and the results under `results/<id>/`, and remote-tracking branches `origin/results/<id>` made by `git update-ref`, and covers the prompt export (the exact text for a template, one entry per release, setup, and input id however many attempts and experiments, a missing template, a template that differs from the manifest's prompt versions), discovery, the skipped folder, a branch-only experiment, a branch overriding a folder, `--remote`, `min_release` (skipped and missing), attempt fields, order, and re-validated outcomes, `legalMoves`, dropped and skipped records, each metric with its null cases, decision models, a model without prices, provider `unknown`, and the definitions parser. Run `pytest tests/test_site.py`.
