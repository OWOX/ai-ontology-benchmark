# Definitions

Every term below means the same thing in code, configs, records, reports, and docs. Each concept has one name. If a word is used in this project with a meaning that isn't here, add it here first.

## Puzzles

1. **Twisty puzzle.** A puzzle whose parts turn around fixed axes, so that each turn moves pieces to new positions.
2. **Puzzle.** A twisty puzzle covered by the study, implemented as one engine. The current puzzles are the 2x2, 3x3, 4x4, and 5x5 cubes. An octahedral puzzle and a tetrahedral puzzle will be added later. Which exact puzzles they are is still [open](../AGENTS.md#open).
3. **Shape.** The solid a puzzle is built on. The cubes are cubes. The octahedral puzzle, once added, is an octahedron with 8 faces, and the tetrahedral puzzle a tetrahedron with 4 faces. The shape fixes the number of faces and colours.
4. **Cube.** A puzzle with the shape of a cube and six coloured faces. An NxN cube has N layers along each axis: 2x2, 3x3, 4x4, or 5x5.
5. **Engine.** The code for one puzzle. It implements the [puzzle engine interface](../AGENTS.md#puzzle-engine-interface) and is the only place that knows the puzzle's rules.
6. **Registry.** The list that maps each puzzle name to its engine. Adding a puzzle adds one entry.
7. **State.** The arrangement of colours on every face of a puzzle at one moment.
8. **Solved state.** A state where every face shows a single colour. The orientation of the whole puzzle doesn't matter, so a 2x2 turned upside down is still solved. `is_solved()` checks colours this way and never compares with `solved_state()`.
9. **Face turn.** A quarter or half turn of one outer layer of a cube, written as the face letter alone or followed by `'` or `2`, for example `R`, `U'`, and `F2`.
10. **Move.** One turn of one part of the puzzle, written in the puzzle's standard notation. On the cubes, a move is a [face turn](#puzzles) or, on the 4x4 and 5x5, a [wide turn](#puzzles). The cube move groups contain no slice moves and no whole-cube rotations. Whether whole-puzzle rotations, slice moves, and wide moves are moves on the octahedral and tetrahedral puzzles is still [open](../AGENTS.md#open).
11. **Wide turn.** One turn of the two outer layers on one side of a cube together, in the same direction as the [face turn](#puzzles) of that side, written as the face letter followed by `w`, for example `Rw`. It takes the same `'` and `2` endings: `Rw'` and `Rw2`. Only the 4x4 and 5x5 have wide turns.
12. **Wing.** An edge piece off the middle of its edge, so each edge has two. Only the 4x4 and 5x5 have wings. A wing shows two colours, and its two stickers can never swap places, so a flipped wing is not reachable.
13. **Notation.** The standard way to write moves for a puzzle, the one AI models already know from their training data. For the 3x3 cube that is Singmaster notation, for example `R`, `U'`, and `F2`. The 4x4 and 5x5 use WCA notation, which adds the wide turns, for example `Rw`, `Uw'`, and `Fw2`.
14. **Move group.** The full list of moves a puzzle allows, as returned by its engine's `legal_moves()`. It is the only definition of a puzzle's moves. The cube move groups are decided, with no slice moves and no whole-cube rotations: [face turns](#puzzles) on the 2x2 and 3x3, and face turns and [wide turns](#puzzles) on the 4x4 and 5x5. The octahedral and tetrahedral move groups are still [open](../AGENTS.md#open).
15. **Legal move.** A string that exactly matches a move in the puzzle's move group. There is no normalization, so `r` doesn't match `R`, `′` doesn't match `'`, and a move with surrounding spaces doesn't match at all.
16. **Move token.** A string written in the shape of a move in the puzzle's notation, whether or not the puzzle allows it, as decided by the engine's `is_move_token()`. For the cubes that is a face letter (`U`, `R`, `F`, `D`, `L`, or `B`) with an optional layer count and an optional `w`, or a lower-case face letter (a wide move), a slice letter (`M`, `E`, or `S`), or a rotation letter (`x`, `y`, or `z`), then an optional `'` or `2` or both, for example `R`, `r'`, `Rw2`, `3Fw`, `M`, `x2`, and `R2'`. Every legal move is a move token. A move token that isn't a legal move is an impossible move.
17. **Impossible move.** A move token an AI model returns that isn't a legal move for that puzzle. A move that exists on another puzzle but not on this one is impossible here. Prose is not an impossible move: see [abstention](#attempts-and-outcomes).
18. **Scramble.** A sequence of legal moves, chosen from the input seed and applied to the solved state. Two consecutive moves never turn the same part of the puzzle, so no move cancels or merges with the one before it. Each engine defines which moves turn the same part. The engine's `scramble()` draws again when the result is solved, checked with `is_solved()`, so no input starts solved.
19. **Scramble depth.** The number of moves in a scramble. Config lists one or more depths, either for every puzzle or for each puzzle on its own, and every input records its own. Depth is an upper bound on the optimal distance to solved, not a measure of it, because a scramble can happen to end close to solved.
20. **Scramble count.** The number of scrambles `generate` makes for each puzzle and scramble depth. A config parameter.
21. **Seed.** The number in config that makes the random choices in `generate` repeatable. The same config, including the seed, always produces the same input set.
22. **Input seed.** The seed for one input, which `generate` derives from the seed and the input's position in the input set. Every scramble and corruption uses its input's seed, so no two inputs share their random choices.
23. **Rendered state.** The text form of a state that goes into the prompt, produced by the engine's `render()`. It is the same under every setup.
24. **Corruption.** The change the engine's `corrupt()` applies to a valid state to make an invalid one. Every invalid input records its corruption. Its description starts with its **corruption type**, two words naming the kind of change, followed by the pieces it changed: `twisted corner`, `flipped edge`, `flipped wing`, `swapped corners`, `swapped edges`, or `recoloured sticker`.

## Inputs

1. **Input.** One frozen puzzle state given to an AI model. It records its id, input set id, input seed, puzzle, state, scramble, scramble depth, and validity label. An invalid input also records its source input id and its corruption.
2. **Valid input.** An input whose state can be reached from the solved state by legal moves.
3. **Invalid input.** An input whose state can't be reached from the solved state by legal moves. `generate` makes one as an extra copy of a valid input, its source, and applies a corruption under its own input seed. The source stays in the input set. The invalid input keeps the scramble and scramble depth of its source.
4. **Source input id.** The id of the valid input an invalid input was made from.
5. **Validity label.** The valid or invalid label `generate` gives each input. The label is authoritative. `load_state()` only checks it, and a disagreement raises an error, because it means a bug in the engine or in `generate`.
6. **Valid/invalid split.** The share of valid inputs for which `generate` also makes an invalid copy. A config parameter. A split of 0.25 makes one invalid input for every four valid ones, so 20% of the inputs are invalid.
7. **Input set.** All inputs made by one `generate` call, under one config.
8. **Input set id.** The id of an input set. It is the major number of the release that first holds the input set. Every input and every raw record carries it.
9. **Frozen.** Written once and never changed again. A different input set needs a new major release.
10. **Development input set.** Input sets 1 and 2, in releases 1.x and 2.x. Prompts were changed while the results of input set 1 were read, so the results on either set show how the method was built and are not evidence for the research question.
11. **Held-out input set.** The input set frozen in release 3.0.0 from a new seed, with the prompts and assessment as they stand when it is cut. Its results are the evidence for the research question.

## Releases and experiments

1. **Release.** A frozen bundle in `releases/<release version>/` that holds everything an AI model sees and everything that judges it: the input set, the prompt templates, and the assessment. Each release has a git tag `release-<release version>`.
2. **Release version.** `MAJOR.MINOR.PATCH`. A new input set bumps MAJOR. A prompt change with the same input set bumps MINOR. An assessment fix bumps PATCH.
3. **Mirror.** A patch release is a mirror of the release before it, or of the newest release of an older minor line when released with `--base`: its input set and every prompt version are identical, and only the assessment differs. A patch release may also add `decision_prompt_versions` to a release that lacked them, because no earlier raw record used them. Raw records made under one release are scored under any of its mirrors without calling an AI model again.
4. **Assessment.** The code that judges attempts and computes metrics: the validator, the engines, the raw file reader (`src/run/raw.py`), `evaluate`, the metrics (`src/evaluate/metrics.py`), the decision loop, and the code that builds its states. The code that only formats the experiment report isn't part of it. A release pins the assessment as one hash over those files.
5. **Experiment.** One `run` of every AI model in an experiment config over one release, and the reports computed from it.
6. **Experiment id.** The name of an experiment config file, without the extension. Every raw record carries it.
7. **Experiment report.** The Markdown file `results/<experiment id>/<release version>.md`. It starts with the release it was scored under, and it links to the release's inputs and prompts instead of copying them.

## Workflows

1. **`generate`.** Builds an input set once. It never talks to an AI model. Only `release` calls it, for a major release.
2. **`release`.** Freezes a new release from the current input set, prompt templates, and assessment, and refuses if the change doesn't match the version bump.
3. **`run`.** Sends every input of one release to every AI model under every setup, validates each attempt, and appends one raw record per attempt. It never changes a release.
4. **`evaluate`.** Re-validates every attempt of one experiment from its raw response under one release, then computes the metrics into reports. It never edits raw records.
5. **Validator.** The deterministic code that turns a raw response into parsed moves, flags, a move count, and an outcome. `run` calls it before writing each raw record, and `evaluate` calls it again. If a validator fix changes an outcome, the reports follow the outcome from `evaluate`, and the raw record stays as written. No AI model judges another AI model.
6. **Parallel requests.** The number of attempts `run` keeps in flight at once in one process, set with `--parallel`. It changes how fast an experiment runs and never what any attempt sends or records.

## Setups

1. **AI model.** The language model being tested. Which ones are tested comes from config.
2. **System-1 model.** An AI model that answers directly, without a separate reasoning step before the answer.
3. **Decision model.** An AI model that chooses among options defined in the request and never generates text. It answers through a per-move loop of [calls](#attempts-and-outcomes), so it can't return an impossible move, though it can choose a [decoy reason](#attempts-and-outcomes). Its options are the [decision options](#setups).
4. **System-2 model.** An AI model trained to reason in tokens before it answers. It stays a system-2 model when an experiment runs it with reasoning switched off. Which kind an AI model is comes from the `kind` field of its entry in config.
5. **Ontology model.** The rules of the system the AI model works in. For a puzzle, that means its pieces, its legal moves, and what each move does.
6. **Setup.** How the ontology model goes into the prompt. There are three setups, and every input goes through all three.
7. **No model.** The setup where the prompt asks the AI model to solve the puzzle and gives no rules.
8. **Descriptive model.** The setup where the prompt explains the rules: what the puzzle is, how its moves work, and what the notation means. The AI model chooses moves on its own.
9. **Prescriptive model.** The setup where the prompt lists the puzzle's move group, exactly as `legal_moves()` returns it, and the AI model must pick every move from that list. Only the prompt states the list. The output schema doesn't enforce it, so a move off the list is still possible, and it is an impossible move.
10. **Prompt.** The full text sent to the AI model for one attempt. It contains the rendered state and never the scramble, because reversing the scramble solves the puzzle. It is the same for every AI model under the same setup and input.
11. **Prompt version.** The version of the prompt text for one setup and puzzle in a release: the first 12 hex characters of one sha256 over every prompt built for that setup and puzzle, in input order. A change to the template, to `render()`, or to `legal_moves()` gives a new version.
12. **Decision options.** The options of a decision model's move question: one per legal move, with id `move_<n>`, where `<n>` is the move's position in `legal_moves()` from 1, plus `done`, which says the moves so far solve the puzzle, and one option per [mismatch reason](#attempts-and-outcomes), with id `mismatch_<n>`, where `<n>` is the reason's position in the offered reasons from 1, each saying the state can't be reached from the solved state by legal moves for that reason. Choosing `done` or a `mismatch_<n>` option ends the attempt. A release without mismatch reasons offers the single option `mismatch` instead. The request holds one question, `next_move`, a choice among the options.
13. **Decision prompt version.** The version of what a decision model is sent for one setup and puzzle in a release: the first 12 hex characters of one sha256 over the bytes of `prompts/decision/questions.txt`, then, for every input in order, its state as the decision model first receives it (the prompt, then `Moves so far: none`) and its request's questions object as JSON with sorted keys. A change to the template, to `render()`, to `legal_moves()`, to the questions file, or to how the state or the request is built gives a new version. It changes no [prompt version](#setups).
14. **Reasoning effort.** How much an AI model reasons before it answers, one of `low`, `medium`, or `high`, set once per experiment in config and sent to every system-2 model in the provider's own parameter. Fixing it keeps the comparison between providers about ability, not about how long each provider lets its model think. An experiment config without it ran at each provider's default.

## Attempts and outcomes

1. **Attempt.** One or more requests to one AI model, under one setup, on one input. A decision model makes one request per move. Each input gets as many attempts per AI model and setup as config says.
2. **Attempt number.** The position of an attempt among the attempts for the same input, AI model, and setup, starting at 1.
3. **Raw record.** The stored result of one attempt in `results/<experiment id>/raw/`. It is never edited.
4. **Raw response.** The full text the API returned for an attempt, stored as received. For a decision model, it is the JSON array of the answers of every completed call, in order.
5. **Report.** The experiment report and five CSVs (metrics, paired, detection, corruption, and reasons), computed by `evaluate` from raw records, one release, and config.
6. **Parsed moves.** The list of moves read from the AI model's output, in the order given: the tokens of its move lines. A line is a **move line** when it splits on whitespace into one or more tokens and every token is a [move token](#puzzles). A line is a **decorated move line** when it does so only after it is split on whitespace and commas and every token that is only a numeric or bullet marker (`1.`, `1)`, `-`, `*`, or `•`) is dropped, a marker glued to the first token left after those is removed, and a single letter with a `.` or `)` as that first token, as in `b)`, is dropped (a lettered marker counts only as the first token left after any numeric or bullet markers, and a capital letter that is a [move token](#puzzles) is kept, as in `R.`), and each token has its surrounding backticks, asterisks, underscores, full stops, parentheses, and straight double quotes stripped, with empty tokens dropped, as in `1. R`, `` `R` ``, or `R, U, F`. Each pair of straight double quotes around a token is stripped in turn, so any number of nested pairs go, as in `""R""`. A **MISMATCH line** is a line that is exactly `MISMATCH`, one space, and one of the offered [mismatch reasons](#attempts-and-outcomes), as in `MISMATCH twisted corner`. A **decorated MISMATCH line** is any other line whose first token left after that stripping is `MISMATCH`, as in `**MISMATCH twisted corner**`, `MISMATCH twisted corner.`, `MISMATCH` alone, or `MISMATCH the colours look wrong`. Its reason is the tokens after `MISMATCH`, joined with single spaces. Under a release without mismatch reasons, the MISMATCH line is exactly `MISMATCH`, and a decorated MISMATCH line has `MISMATCH` as its only token. Every other line is a **prose line**. The parsed moves are the tokens of the move lines and decorated move lines, in order. Empty for outcome `abstention`. One Markdown code fence, with an optional language tag of letters only, around the whole response is stripped before its lines are read, so a fenced answer reads as the same answer without the fence. A fence around only part of a response is not stripped, and its fence lines are read like any other line. For a decision model, the moves behind each call's `next_move` choice, in call order, before the first `done` or mismatch choice.
7. **Malformed output.** A response the validator can't use: it has no lines left once a surrounding code fence and blank lines are dropped, so a response that is only an empty fence is malformed output (for a decision model, it doesn't parse as the array of answers, where every call holds a `next_move` choice the call offered), or the AI model or a content filter refused to answer. A content-filter refusal counts here even when the API returns it as an error, and it is never retried. A response cut off at the token limit is not malformed output: it is `truncated`. Prose instead of moves is not malformed output either: with no move line, decorated or not, and no `MISMATCH` line it is an `abstention`, and a prose line beside legal moves is a `format_error`.
8. **Infrastructure failure.** A network error, timeout, or rate limit. `run` retries it up to the retry cap. When the cap is reached, the raw response is empty, except that a decision-model attempt keeps the calls that completed, and the retry cap counts across all its calls. A [budget stop](#prices) that ends an attempt after its first call, or stops one of its retries, also gives outcome `infrastructure_failure`: the attempt keeps its paid tokens and the calls that completed. A budget stop before the first call writes no record.
9. **Retry cap.** The maximum number of retries for one attempt. A config parameter.
10. **Mismatch flag.** The flag set only when the whole response is a single MISMATCH line, which says the input describes a puzzle that can't be reached from the solved state by legal moves. For a decision model, it is on when the call that ended the attempt chose a `mismatch_<n>` option, or `mismatch` under a release without mismatch reasons. Off for every other outcome, including `format_error`, `truncated`, `malformed_output`, and `infrastructure_failure`.
11. **Hallucination flag.** True when the parsed moves contain at least one impossible move, or the mismatch reason is a [decoy reason](#attempts-and-outcomes), which is outcome `hallucination`. False for outcomes `abstention`, `format_error`, `success`, and `failure`, and for `infrastructure_failure`, `truncated`, and `malformed_output` of a text model, which have nothing to judge. For a decision model, true when it chose a decoy reason and false otherwise, except under a release without mismatch reasons, where it is null for every outcome, because a decision model can't return an impossible move.
12. **Solved.** The validator applied every parsed move to the input state in order, every move was legal, and `is_solved()` is true for the final state. An empty move list is never solved, because no input starts solved.
13. **Expected result.** For a valid input, the puzzle ends solved and the mismatch flag is off. For an invalid input, the mismatch flag is on.
14. **Outcome.** The one result the validator gives each attempt, checked in this order:
    1. `infrastructure_failure`: the retry cap was reached, or a [budget stop](#prices) ended the attempt, so there is no complete response to judge.
    2. `truncated`: the stop reason is `truncated`, so the response was cut off at the token limit.
    3. `malformed_output`: the stop reason is `refused` (a refusal by the API or a content filter), no line is left, or, for a decision model, the raw response doesn't parse as the array of answers.
    4. `abstention`: there is no move line, no decorated move line, and no MISMATCH line, plain or decorated, except that a response whose only line is a MISMATCH line is never an abstention. The AI model answered in prose, for example to say it can't solve the puzzle.
    5. `hallucination`: a parsed move is not a legal move, or the mismatch reason is a decoy reason, so the hallucination flag is true. The attempt fails, even if the final state happens to be solved or the mismatch flag is on.
    6. `format_error`: every parsed move is legal, but the response isn't in the required layout: it has a prose line, a move line with more than one token or with whitespace around its token, a decorated move line, a MISMATCH line beside any other line, or a decorated MISMATCH line, including one whose reason isn't offered. The mismatch flag is off.
    7. `success`: the expected result is reached.
    8. `failure`: every move was legal and the layout was right, but the expected result is missed. That means a valid input left unsolved or flagged, or an invalid input left unflagged.
15. **Call.** One request inside an attempt. An attempt by a [decision model](#setups) is a loop of calls, one per move, and every other attempt is one call plus its retries. Retries of a call count against the [retry cap](#attempts-and-outcomes) of the attempt.
16. **False MISMATCH.** A claim that a solvable puzzle can't be solved: the mismatch flag is on for an attempt on a valid input. Its outcome is `failure`, or `hallucination` when its reason is a decoy reason. With any other reason it is a wrong answer, not a hallucination, because `MISMATCH` is one of the two answers the prompt offers. Every reason given for it is wrong, because a valid input has no corruption, so a false MISMATCH is a [false negative](#attempts-and-outcomes) and counts against [critical thinking](#metrics).
17. **Mismatch reason.** The cause an AI model gives after `MISMATCH`: one of the reasons the engine's `mismatch_reasons()` returns, or `other`. The prompt offers them all, in that order, under every setup. On a cube they are `twisted corner`, `flipped edge`, `flipped wing`, `swapped corners`, `swapped edges`, `recoloured sticker`, and `twisted centre`, on every size, so the list names pieces that some cubes don't have. The mismatch reason of an attempt is the reason on its first MISMATCH line or decorated MISMATCH line whose reason is offered, and empty when there is none. A release made before mismatch reasons existed asks for the bare line `MISMATCH`, and its attempts have no mismatch reason.
18. **Decoy reason.** A mismatch reason that no state of the puzzle can show, offered so that choosing it can be caught. On the cubes it is `twisted centre`: a centre shows one sticker, so no rendered state can show it twisted. Choosing a decoy reason claims evidence that isn't in the state, so it is a hallucination.
19. **Diagnosis.** An attempt on an invalid input whose mismatch flag is on and whose mismatch reason is the input's corruption type. `other` and a decoy reason are never a diagnosis.
20. **Classified answer.** An attempt with outcome `success`, `failure`, or `hallucination`: one the validator could judge as right or wrong. An attempt claims that the puzzle can't be solved when its mismatch flag is on or it has no parsed moves, and claims a solution otherwise. Outcomes `abstention`, `format_error`, `truncated`, `malformed_output`, and `infrastructure_failure` give no classified answer.
21. **True positive.** A classified answer that claims a solution and has outcome `success`, which is a valid input solved.
22. **False positive.** A classified answer that claims a solution and has any other classified outcome: legal moves that leave the puzzle unsolved, an impossible move, or moves on an invalid input.
23. **True negative.** A classified answer that claims the puzzle can't be solved, on an invalid input, with the mismatch flag on and, under a release with mismatch reasons, its corruption type as the reason. Without mismatch reasons the prompt asked for no reason, so a flagged invalid input is a true negative.
24. **False negative.** Any other classified answer that claims the puzzle can't be solved: a [false MISMATCH](#attempts-and-outcomes) on a valid input, a decision model's moves followed by a mismatch choice that is not a true negative, or, under a release with mismatch reasons, a MISMATCH on an invalid input with a wrong reason, `other`, or a decoy reason.

## Recorded values

Raw records store these values. Invariant 13 in [AGENTS.md](../AGENTS.md#invariants) lists every field of a raw record.

1. **Move count.** The number of parsed moves, in the half-turn metric. Each impossible move counts as one. Set for outcomes `hallucination`, `format_error`, `success`, and `failure`. Empty for `infrastructure_failure`, `truncated`, `malformed_output`, and `abstention`.
2. **Half-turn metric.** The way moves are counted: any turn of one part, including a half turn such as `R2`, counts as one move. A wide turn counts as one move. The cubes have no whole-puzzle rotations or slice moves. How they count on the octahedral and tetrahedral puzzles is still [open](../AGENTS.md#open).
3. **Input tokens and output tokens.** The token counts the API reports for the call that produced the raw response, stored as returned. For a decision model, the sums over its completed calls. Zero for outcome `infrastructure_failure`, except that a decision model with completed calls keeps their sums, so cost counts them. For Google, output tokens are `candidates_token_count + thoughts_token_count`, both as returned, because Gemini bills thoughts as output. The other providers' output counts already include reasoning tokens.
4. **Retry input tokens and retry output tokens.** The token counts the API reports for every call in the attempt that failed, retried or not, summed and stored as returned. Zero when no call failed or the API reported no counts.
5. **Latency.** The time from sending the request to receiving the full response, for the call that produced the raw response. For a decision model, the sum over its completed calls. Empty for outcome `infrastructure_failure`, except that a decision model with completed calls keeps their sum.
6. **Stop reason.** How the call that produced the raw response ended (for a decision model, the last call of the attempt): `ok`, `truncated`, `refused`, or `infrastructure_failure`. The validator needs it, because a truncated or refused response can look like valid JSON.
7. **Served model.** The AI model id the API reported for the call, stored as returned. For a decision model, the distinct values over its calls, in first-seen order, joined with `,`. Empty when the API reports none for a call, and never filled in with the id the request asked for. Empty for outcome `infrastructure_failure`, except that a decision model with completed calls keeps its calls' values. It shows when a model alias pointed at a different model than expected.
8. **Decision flag.** True when the attempt was made by a [decision model](#setups), false otherwise. Scoring reads it from the raw record to choose how the raw response is parsed. A record written before the field existed falls back to the model's provider in the experiment config.
9. **Requested model.** The `api_model_id` the request asked for, recorded for every provider and every outcome, including `infrastructure_failure`. Compare it with the served model to see when an alias pointed elsewhere.
10. **Max moves.** The cap on the moves in one [decision-model](#setups) attempt. The attempt ends when its moves reach it. A config parameter, default twice the largest scramble depth of the input's puzzle in the release.
11. **Mismatch reason.** The [mismatch reason](#attempts-and-outcomes) of the attempt, or empty when it has none. A record written before the field existed is read as empty, and `evaluate` takes the reason from re-validation anyway.

## Prices

1. **Token price.** The price per input token and per output token for each AI model, kept in config.
2. **Cost.** For one raw record, its input and retry input tokens times the input token price, plus its output and retry output tokens times the output token price, in USD.
3. **Worst-case request cost.** The most one request can cost, per call for a decision model, whose request then holds the state with `max_moves` moves and the questions object: the request's characters divided by 4, rounded up, as input tokens, plus `max_output_tokens` as output tokens, at the AI model's token prices.
4. **Budget.** A cost limit in USD in the experiment config. There are three:
   1. **Request budget.** No worst-case request cost may exceed it. Default 2.00 USD.
   2. **Model budget.** The cost of one AI model's raw records in one experiment may not exceed it. Default 25.00 USD.
   3. **Experiment budget.** The cost of all raw records in one experiment may not exceed it. Default 50.00 USD.
5. **Budget stop.** The refusal of `run` to send the next request of an attempt, because its worst-case request cost added to the cost already spent would pass the model budget or the experiment budget. `run` then exits with code 1, and a later run with a raised budget resumes.

## Metrics

`evaluate` computes every metric. No metric is stored in raw records. Reports split each metric by puzzle, setup, AI model, scramble depth, and validity label, except balanced precision, critical thinking, balanced accuracy, and cost efficiency, which combine both validity labels, and the paired setup test, which pools scramble depths. Attempts with outcome `infrastructure_failure` are left out of every rate, consistency, and latency, and counted on their own, so the denominators never change silently. They still count in tokens per attempt and cost efficiency, because their failed calls cost money.

Every rate is reported with its denominator `n`, the number of attempts, the number of inputs behind it, and a 95% bootstrap interval over inputs: inputs are drawn with replacement 2000 times, each draw keeps all attempts of the inputs drawn, and the interval is the 2.5th and 97.5th percentile of the rate over the draws. Attempts on one input aren't independent, so resampling attempts would make the interval too narrow. The draws come from a fixed seed, so the same raw records always give the same interval. The interval is n/a when fewer than 2 inputs are behind the rate. A metric that combines both validity labels draws valid and invalid inputs separately, each side as many as it has.

1. **Precision.** For one validity label, the share of [classified answers](#attempts-and-outcomes) that are right: (true positives + true negatives) / (true positives + false positives + true negatives + false negatives). n/a when there is no classified answer.
2. **Balanced precision.** For one AI model, setup, and puzzle, the mean of the precision on valid inputs and the precision on invalid inputs. It is the main measure of how often an answer is right. Taking the mean of the two labels keeps it independent of the valid/invalid split, so input sets with different splits compare. n/a when either precision is.
3. **Coverage.** The share of attempts that are classified answers. Precision leaves out abstentions and other answers it can't judge, so coverage is reported beside it: an AI model that abstains whenever it is unsure keeps a high precision and gets a low coverage.
4. **Hallucination rate.** The share of attempts with at least one impossible move, among the attempts that gave moves. An attempt gave moves when it has at least one parsed move. MISMATCH answers, abstentions, truncated output, and malformed output give none, so they are left out of the rate. One impossible move is enough to make an attempt count. A decoy reason counts in the reason hallucination rate instead. n/a when no attempt gave moves, and for decision models, which can't return an impossible move.
5. **Reason hallucination rate.** The share of attempts whose mismatch reason is a [decoy reason](#attempts-and-outcomes), among the attempts with a mismatch reason, on valid and invalid inputs. It covers decision models too. n/a when no attempt has a mismatch reason, and under a release without mismatch reasons.
6. **Critical thinking.** How well an AI model judges whether a puzzle can be solved at all, and why not. For one AI model, setup, and puzzle, the mean of the diagnosis rate and one minus the false mismatch rate. A MISMATCH with the wrong reason earns nothing, and a false MISMATCH costs as much as a missed diagnosis, so only a value above 0.5 shows that the AI model finds the corruption without inventing one. It doesn't depend on the valid/invalid split. Reports show beside it the best score of one fixed answer: `MISMATCH` with the puzzle's most common corruption type in the input set, whose diagnosis rate is that type's share and whose false mismatch rate is 1.0. n/a under a release without mismatch reasons.
7. **Mismatch detection rate.** The share of attempts on invalid inputs where the mismatch flag is on, whatever the outcome or reason. Truncated output, malformed output, abstention, and format errors count as not detected.
8. **False mismatch rate.** The share of attempts on valid inputs that are a [false MISMATCH](#attempts-and-outcomes). Truncated output, malformed output, abstention, and format errors count as not flagged.
9. **Diagnosis rate.** The share of attempts on invalid inputs that are a [diagnosis](#attempts-and-outcomes). Truncated output, malformed output, abstention, and format errors count as not diagnosed. n/a under a release without mismatch reasons.
10. **Balanced accuracy.** For one AI model, setup, and puzzle, the mean of the mismatch detection rate and one minus the false mismatch rate. It reads the flag only, not the reason. 0.5 is what answering MISMATCH always, or never, scores, so only a value above 0.5 shows detection.
11. **Malformed output rate.** The share of attempts with outcome `malformed_output`. Malformed output never counts as a hallucination.
12. **Truncation rate.** The share of attempts with outcome `truncated`.
13. **Abstention rate.** The share of attempts with outcome `abstention`.
14. **Format error rate.** The share of attempts with outcome `format_error`.
15. **Infrastructure failure count.** The number of attempts with outcome `infrastructure_failure`.
16. **Consistency.** For one input, AI model, and setup, the share of attempts with the most common outcome. Reported as the mean over inputs. A value of 1.0 means every attempt gave the same outcome. Reported as n/a for an input with fewer than two attempts left after exclusions.
17. **Latency per attempt.** The mean latency per attempt.
18. **Tokens per attempt.** The mean input and output tokens per attempt, including retry tokens.
19. **Cost efficiency.** The cost of one right answer: the mean cost per attempt, including retry tokens and infrastructure failures, divided by balanced precision times coverage. Abstaining doesn't make an AI model look cheaper, because it lowers coverage. Cost comes from token counts and token prices, never from a number stored in raw records. n/a when balanced precision or coverage is 0 or n/a.
20. **Always-MISMATCH baseline.** The scores of an answerer that returns `MISMATCH` with one fixed reason on every input: detection rate 1.0, false mismatch rate 1.0, balanced accuracy 0.5, precision 0 on valid inputs and the reason's share of corruption types on invalid inputs, and critical thinking at most 0.5. Reports show it beside every balanced accuracy and critical thinking value.
21. **Paired setup test.** For one AI model, puzzle, validity label, and metric, a comparison of two setups on the same inputs. The metric is precision, the hallucination rate, the mismatch detection rate (invalid inputs only), or the diagnosis rate (invalid inputs only, under a release with mismatch reasons). The hallucination rate is skipped for a decision model. Each input gets one share per setup: the share of its attempts, with outcome `infrastructure_failure` left out, that are a hit for the metric: a true positive or true negative for precision, at least one impossible move for the hallucination rate, the mismatch flag on for the mismatch detection rate, and a diagnosis for the diagnosis rate. For precision the share is over the classified answers, and for the hallucination rate over the attempts that gave moves, so an input with none under a setup has no share there and is not paired for that pair. The comparison is pooled over scramble depths, never over validity labels. The test is an exact two-sided sign test on the inputs whose shares differ. An input is paired only when at least one attempt that is not `infrastructure_failure` is left under each of the two setups. It reports the inputs paired, the inputs where each setup is higher, the mean share difference (second setup minus first), the p-value, and the Holm-adjusted p-value over the setup pairs that have at least one paired input. A pair with none has p-value `n/a` and is left out of that family. The difference is significant when the Holm-adjusted p-value is below 0.05. Every setup sees the same inputs (invariant 6), so pairing removes input difficulty from the comparison. Using the input as the unit keeps repeated attempts on one input from counting as independent. The p-value is `n/a` when no input is paired, and 1.0 when no paired input differs.
22. **Paired model test.** The [paired setup test](#metrics) with two AI models in place of two setups. For one puzzle and metric, each input gets one share per AI model, pooled over the chosen setups and releases. Inputs are matched on input set id and input id. The metric can be any rate in this list that is computed for one validity label. For precision, a hit is a true positive or true negative, over the classified answers. For the false mismatch rate, a hit is the mismatch flag on a valid input. For the malformed output, truncation, abstention, and format error rates, it is the matching outcome. For the hallucination rate, the share is over the attempts that gave moves, and an input with none for an AI model has no share for it. A hallucination rate that is n/a for a decision model is left out of the test. It is an exact two-sided sign test on the paired inputs whose shares differ, and its p-values are Holm-adjusted over the tests named where it is used. It is computed for display only and never goes into a report.
